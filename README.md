# Spectra

Spectra lets you write Minecraft: Java Edition server gameplay in TypeScript or JavaScript and ship web-based
UIs (screens and HUD layers) to players on the fly.

## Layout

| Path | What it is |
|---|---|
| `packages/api` | Public Java API for other plugins: client capabilities, views, HTTP/WebSocket routes for views, and resource namespaces. |
| `packages/typegen` | Generates TypeScript declarations from Java classes, with parameter names and Javadoc extracted from sources jars. |
| `packages/protocol` | Wire protocol shared by every server and client. Has no dependencies. See [PROTOCOL.md](packages/protocol/PROTOCOL.md). |
| `packages/core` | Platform-independent server logic: client handshakes and capabilities, resource sync, views, and the script lifecycle with hot reload. |
| `packages/runtime-js` | GraalJS runtime: a shared engine, one ES-module context per script, web-style timers. |
| `apps/paper` | Paper 26.3 plugin (the primary server target). |
| `apps/fabric` | Fabric 26.3 client mod that renders the UIs. See [its README](apps/fabric/README.md). |
| `apps/spectra-sdk`, `apps/create-spectra` | npm SDK and project templates: a dev server, esbuild watch, and typings. |
| `apps/docs` | Documentation site. |

## Building

Java modules need nothing installed beyond a JDK to launch Gradle. Gradle provisions Java 25 automatically.

```bash
./gradlew build
```

```bash
npm ci && npm run build:js
```

The Paper plugin is written to `apps/paper/build/libs/spectra-paper-<version>.jar`, and the client mod to `apps/fabric/build/libs/`.

## Writing scripts

Scripts are ES modules, and code written for the web or for Node, Bun or Deno mostly runs unchanged.

- **Web globals:** `fetch`, `Request`, `Response`, `Headers`, `URL`, `TextEncoder`/`TextDecoder`, `EventTarget`, `AbortController`, `WebSocket`, `crypto`, `structuredClone`, timers in milliseconds.
- **Node builtins:** `node:path`, `fs`, `events`, `util`, `os`, `buffer`, `crypto`, `timers`, `url`, `assert`, `process`.
- **Minecraft events:** `addEventListener(org.bukkit.event.player.PlayerJoinEvent, ...)`.
- **Commands:** `addCommand(...)`.
- **World generation:** export `getDefaultWorldGenerator` / `getDefaultBiomeProvider`.
- **Views:** answer views' `fetch('/api/...')` and `new WebSocket('/api/...')` with `addEventListener('fetch', e => e.respondWith(...))` and `addEventListener('websocket', e => e.accept())`.

TypeScript types for Paper and every installed plugin are generated by the server at startup. `spectra-sdk dev` copies them into `.spectra/types/`.

## Building on Spectra from Java

Add `com.mathhulk.spectra:api` as a `compileOnly` dependency, declare `depend: [Spectra]`, and use `Spectra.get()` (it is also registered with Bukkit's `ServicesManager`). From there you can:

- check a player's client capabilities and enforce them, or not;
- open screens and HUD layers;
- register HTTP and WebSocket routes for views;
- ship your own UI resources under a namespace.

## Views

Views are served from a private origin per server.

- **Server API:** `fetch('/api/...')` and `new WebSocket('/api/...')` reach the server over the Spectra protocol.
- **Internet access:** views may contact internet origins the server allowlists in `client.network-allow`. Players can turn this off.
- **Minimaps:** `/_spectra/game/player` and `/_spectra/game/map.png` expose client-side data such as player position and terrain.
- **HUD layers:** all HUD layers share one browser per HUD slot.

## Scripts and performance

Scripts live in `<server>/scripts` and UI resources in `plugins/Spectra/resources`. Both reload when their files change.

GraalJS runs scripts in interpreter mode on a standard JDK. For compiled performance, run the server on GraalVM. Spectra logs which mode is active at startup.
